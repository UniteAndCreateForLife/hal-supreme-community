# Collaboration Networks and Growth Targets

Checked: 2026-10-17

This is a working list of external communities and programs where HAL SUPREME can find contributors, mentors, collaborators, fiscal support, or public build opportunities. Re-check current rules and deadlines before applying or posting.

## Tier 1: build contributor reach now

### GitHub Open Source

Why it fits:
- HAL already has public repositories and contribution paths.
- GitHub is the canonical place for Issues, PRs, Discussions, contributor credit, and public engineering history.

Actions:
- maintain 10-20 genuinely useful good-first issues;
- publish a contributor roadmap and project ideas;
- keep Discussions active;
- add screenshots/demos to issues where visual work is requested;
- make acceptance criteria explicit.

Reference: https://github.com/open-source

### Hugging Face Hub

Why it fits:
- strong overlap with open AI, models, datasets, demos, and Spaces;
- useful for shareable HAL demos and evaluation fixtures.

Actions:
- keep public Spaces focused and reproducible;
- publish small public datasets/evals only when they contain no private user data;
- cross-link Spaces back to GitHub contributor tasks;
- invite collaborators around concrete demos rather than broad promotion.

Reference: https://huggingface.co/docs/hub/index

### Open Collective / Open Source Collective

Why it fits:
- open-source fiscal hosting and transparent project finances;
- useful for community-supported infrastructure, sponsorship, and contributor expenses.

Actions:
- keep fiscal-sponsorship status accurate;
- connect repository, website, Discord, and other community links;
- define transparent funding goals tied to public work;
- document how funds would support infrastructure, moderation, design, contributor work, or events.

References:
- https://opencollective.com/fiscal-hosting
- https://opencollective.com/opensource

## Tier 2: structured contributor programs

### Google Summer of Code ecosystem

GSoC is a global mentoring program for bringing contributors into open source. HAL is not a 2026 mentoring organization, but the model is worth adopting internally now and preparing for future organization applications.

Actions:
- maintain a project-ideas page;
- define mentors/owners;
- make project scopes 12+ week friendly;
- create newcomer onboarding that does not require private infrastructure;
- study accepted AI/open-source mentoring organizations and their contributor guides.

Reference: https://summerofcode.withgoogle.com/

### GirlScript Summer of Code / similar open-source cohorts

Programs such as GSSoC connect contributors to curated open-source projects and use issue difficulty / contribution quality to structure participation.

Actions:
- evaluate project-registration windows;
- keep contribution guides, labels, and task scopes ready;
- avoid gamifying low-quality PR volume; quality and reviewability matter more.

Reference: https://github.com/GSSoC26/family

### Open Source Connect Global and regional communities

Contributor-learning programs can provide newcomers looking for real projects.

Actions:
- watch current project-registration calls;
- offer beginner-friendly docs, test, accessibility, and integration tasks;
- pair contributors with clear maintainers.

Example: https://github.com/Open-Source-Connect/OSCG-2026

## Tier 3: AI / infrastructure alliances

### LF AI & Data

Potential value:
- AI/data ecosystem networking;
- vendor-neutral technical content;
- community events and project-adoption exposure.

This may involve membership costs, so treat it as research/relationship-building first rather than assuming paid membership.

Reference: https://lfaidata.foundation/join/

### Open-source umbrella communities

Examples worth learning from include FOSSASIA, Open Science Labs, NumFOCUS, AOSSIE, and other mentoring organizations that have repeatable newcomer funnels.

Reference list: https://summerofcode.withgoogle.com/programs/2026/organizations

## Build competitions and public demos

### Devpost

Useful for:
- public deadlines that force shippable demos;
- team formation;
- sponsor/tool relationships;
- public project pages.

Rules vary by event. Some events require all submission code to be written during the event, so existing HAL code cannot automatically be used as an eligible submission.

Reference: https://devpost.com/hackathons?status=open

## Creator / arts collaboration

HAL should also recruit beyond software:
- musicians;
- video editors;
- motion designers;
- 3D artists;
- sound designers;
- accessibility reviewers;
- community moderators;
- technical writers.

The public project system should support media contributions with explicit ownership, remix permissions, attribution, and provenance rather than treating every contribution as code.

## Network operating model

For every external network:

1. create a concrete public landing task or project;
2. name the maintainer/owner;
3. publish acceptance criteria;
4. provide a safe public dataset/demo or fixture;
5. make contribution credit visible;
6. route accepted work through normal review;
7. record where the contributor discovered HAL so we learn which networks actually work.

## Metrics to track

- unique contributors per month;
- first PR -> second PR conversion;
- issue claim -> accepted contribution rate;
- median review turnaround;
- number of active project rooms;
- accepted code vs docs vs design vs media contributions;
- contributors by discovery network;
- retention at 30/90 days;
- public demos shipped;
- sponsorship/fiscal-hosting conversion;
- number of collaborations that continue after the initial event.
